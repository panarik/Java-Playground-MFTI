# План на семинар

На семинаре будем разбирать как тестраннер кидает эксепшены и как их ловить.
- на примере моего обучающего проекта App-Android-TestFeatures
- на примере продакшен проекта автотестов Детского Мира

Для продакшен проетка несколько эпизодов:
- Перехват на уровне прямого успользования
- Перехват на уровне TestRunner DSL (Без прямого использования)
- перехват с помощью try catch
- перехват с помощью внешних методов

1. Смотрим на проект который только и занимается что кидает экспешены тк это автотесты.
2. Быстрая обработка эксепшена.
3. Ограничение ожидания:
- по времени
- по количеству попыток

### Установка и настройка окружения - Android project

Установка
- git clone https://github.com/panarik/App-Android-TestFeatures
- скачать и установить Android Studio
- сбилдить проект
  - Gradle спросит про версию джавы. Выберите 17-ую.
- Скачать и Установить эмулятор (в UI андроид студии)
  - Версия (13ый андроид)

### Практическая работа
В обучающем андроид проекте мы пофиксили тест путем перехвата эксепшена с ожиданием прямо в классе автотеста.
Таким способом обычно не пишут. Мы это сделали для грубого примера.
Далее я показал на проекте Десткого Мира как обычно перехватывают эксепшены при падении теста.

Практическая - отрефачить код, который мы написали. Вместо просто ожидания сделать цикл и в нем пытаться применить проверку пока она не пройдет.
Цикл должен быть с ограничением:
- по времени
- по количеству попыток.
Действия цикла и попыток проверки нужно логгировать.

Местонахождения исходного автотеста:
Класс - TestSignIn
Метод - test_auth_signIn

Запуск автотеста:
- запущен эмулятор
- кликаем на зеленую стрелку напротив метода автотеста.
