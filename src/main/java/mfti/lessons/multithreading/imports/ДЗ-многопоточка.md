# **Задача №1. Пул потоков** (1 балл)

Необходимо разработать класс, позволяющий реализовать управление процессом параллельного выполнения задач, не вынуждая разработчика явно порождать новые потоки. Полученное решение должно предоставлять возможность:

* создавать новый пул с указанным максимальным числом потоков;  
* задавать список задач для выполнения;  
* управлять процессом завершения работы пула.

Разработанный класс должен иметь как минимум следующие методы:

* Конструктор, задающий число рабочих потоков  
* **public void execute(Runnable task);**  
* **public void shutdownAfterAllTasks();**  
* **public void shutdownNow();**  
* **public boolean isClosed();**

Метод **execute()** отвечает за добавление задачи в очередь исполнения. Задачи должны выполняться рабочими потоками пула. Если в данный момент свободных рабочих потоков нет, задача должна оставаться в очереди до освобождения одного из потоков. Каждая переданная в пул задача должна быть выполнена не более одного раза. Ожидается, что все принятые пулом задачи должны в конечном итоге быть выполнены. Порядок выполнения задач должен соответствовать порядку их помещения в очередь настолько, насколько это возможно с учётом параллельного выполнения. Пул должен поддерживать выполнение нескольких задач одновременно. Например, если пул содержит 4 рабочих потока и в него передано 10 задач, одновременно может выполняться не более 4 задач.

Все публичные методы пула потоков должны быть потокобезопасными (например, если **execute()**  вызывается из двух потоков одновременно – ни одна поставленная в очередь задачу не должна быть потеряна.

Если внутри любой задачи падает исключение, то исполняющий его поток пула не должен умирать, а должен брать следующую задачу.

Пул должен иметь как минимум два состояния: 

* открыт — принимает новые задачи;  
* закрыт — новые задачи не принимает.

После вызова одного из методов завершения работы пул должен перейти в состояние, в котором добавление новых задач невозможно (методы **shutdownAfterAllTasks()** и **shutdownNow()**).

Метод **shutdownAfterAllTasks()** должен выполнить корректное завершение работы пула. После вызова метода: 

* новые задачи не должны приниматься;  
* задачи, уже находящиеся в очереди, должны быть выполнены;  
* метод должен дождаться завершения всех ранее принятых задач;  
* после завершения всех задач рабочие потоки должны завершить работу;  
* после завершения метода пул считается закрытым.

Метод **shutdownNow()** должен инициировать немедленное завершение работы пула. После его вызова: 

* новые задачи не должны приниматься;  
* задачи, находящиеся в очереди и ещё не начавшие выполняться, удаляются из очереди;  
* выполняющимся задачам отправляется сигнал прерывания (**interrupt**);  
* после завершения всех задач рабочие потоки должны завершить работу;   
* после завершения метода пул считается закрытым.  
* Метод **isClosed()** должен возвращать **true**, если пул больше не принимает новые задачи, и **false** в противном случае. 

# **Задача №2. Получение результатов потоков** (1 балл)

Решение, полученное в рамках задачи 1, не описывает процесс получения результатов выполняемых пулом потоков, что может привести к появлению потоков низкого качества. В рамках данного задания ранее полученное решение будет расширено путем внедрения в него различных механизмов получения результатов. 

Метод **execute()** пула потоков должен быть изменен таким образом, чтобы возвращать результат в виде объекта типа **Result**. Данный объект возвращается методом **execute** сразу же после постановки задачи в очередь на исполнение (не ожидая завершения потока). 

Объект **Result** должен обладать следующим списком методов:

* get()  
* onSuccess()  
* onFailure()  
* isFinished()

Метод **get()** ничего не принимает и возвращает значение указанного пользователем типа. Это значение представляет собой результат, сформированный соответствующим потоком. Варианты работы метода, следующие:

* если вычислительный поток еще не завершил расчёт результатов — текущий поток блокируется до её завершения;  
* если вычислительный поток завершился успешно — возвращается результат;  
* если вычислительный поток завершился с исключением — информация об исключении должна быть передана вызывающему коду.

Метод **isFinished()** возвращает состояние результата. Состояние может быть одним из трех вариантов:

* RUNNING – вычислительный поток продолжает работу  
* FINISHED – вычислительный поток записал результат  
* FAILD – вычислительный поток упал с исключением

При порождении **Result** он находится в состоянии RUNNING и затем переходит в завершенное или ошибочное состояние. Другие переходы недопустимы.

Методы onSuccess и onFailure ничего не возвращают, а принимают действие, которое должно быть выполнено в тот момент времени, когда будет получен результат вычислительного потока. Регистрация действия может быть выполнена только до момента перехода объекта **Result** в состояние FINISHED или FAILD. Добавлено может быть несколько действий. Если в зарегистрированном действии возникает исключение – это не меняет тип результата и не мешает выполняться остальным действиям.

# **Задача №3. Управление нагрузкой** (2 балла)

Третья часть задания предполагает усложнение поведения пула потоков путем внедрения концепции разделения задач на быстрые и медленные. Быстрые задачи должны выполняться пулом потоков немедленно, с получением результатов сразу же. Медленные задачи добавляются в очередь и выполняются по мере возможности. При получении задачи пул потоков не знает к какой категории относится переданная ему задача, и должен определить это уже в процессе работы.  
Для этого считаем, что в пуле будет как минимум два потока:

* Поток для быстрых задач. Данный поток всегда один.  
* Поток для медленных задач. Данных потоков может быть много, их количество задается при создании пула потоков.

При создании пула потоков, кроме указания числа медленных потоков, так же можно указать предельное время исполнения для быстрых задач (например, 2 мс). Это время будет использоваться пулом для классификации задач. Таким образом, логика работы пула потоков будет следующая: 

* После добавления задачи она попадает в очередь быстрых задач, откуда она начнет исполняться быстрым потоком.  
* Если результат получен в заданное время, то он указывается в Result и из очереди забирается следующая быстрая задача.   
* Если в заданное время завершить задачу не удалось, она считается медленной и передается в очередь выполнения медленных задач.

Такая реализация потока позволит сделать её такой, чтобы она немедленно, можно сказать “реактивно” реагировала на все простые задачи, не прерывая выполнение таких задач, которые требуют длительных вычислений. Для этого быстрый поток всегда должен быть доступен для выполнения новых быстрых задач, даже если в очереди все еще есть невыполненные медленные задачи.

Вместе с тем, модель многопоточности языка Java не предоставляет механизмов, которые позволили бы перенести выполнение действия с одного потока на другой. В рамках данного задания необходимо предложить такой способ формирования задач, которое позволит выполнять прерывание исполняемого кода для того, чтобы выполнение задачи можно было возобновить позднее.
